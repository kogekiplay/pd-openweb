# HAP 7.5.0 business integration review

Comparison: upstream 391c54a8b → v7.5.0 beb05e38e; fork base d4a7bc0bf. This review describes source evidence and integration. It does not claim live acceptance against the 7.5.0 services.

## Implemented business paths

- Print count limits remain integrated in the existing typed `RecordForm/PrintList.tsx` path. Template settings save `print_count_enabled`, `printLimitEnabled` and `printLimitCount`. Desktop and mobile template printing precheck the actual row IDs. Batch printing filters successful records and displays failed titles; QR/PDF paging repeats prechecks for newly loaded pages. Record menus show template counts and expose count reset to administrators. The fork's vector barcode renderer remains in use.
- ExportSheet loads, saves and submits `exportScore`; its Excel options expose the additional option-score column. Fast export filters retain `advancedSetting`.
- Form defaults use the actual map-provider value (`Number(getMapConfig()) === 1`). Integration SDK signing receives the original URL without repeated URI encoding. Mobile location checks the current environment at interaction time.
- Clearing a related field retains its old row IDs in `keepShowRowIds`; desktop/card/mobile choosers pass those IDs back in their server exclusion exception list. Scan-only fields block manual capsule selection. Draft relation reloads reset the first page and ignore transient empty rendering snapshots.
- Relation table permissions observe `eventPermissions` changes. Member scopes parse malformed JSON safely and discard empty IDs. Dynamic default selection retains source-field enum/settings in dynamic-value, rule and event contexts.
- Existing child-table rows without `updatedControlIds` are omitted from edit patches. Changed rows submit only changed columns and their row ID, preventing hidden related/owner/attachment values omitted by the row API from being cleared. The new `subListPatch.spec.ts` verifies both cases and checks that source rows are not mutated.
- Mobile date bounds are memoized by their timestamps, so equivalent recreated Date values do not reset the wheel selection. Readonly attachment images expose real image elements through their hover layer for browser copying.
- Discussion forwarding respects the disabled-feed flag at both the toolbar and request path, and a synchronous submission lock prevents duplicate comments. The workbench AI connector respects the master AI switch.
- Structured related-record log titles resolve the source title control and display member/department/role names or location text independently of link-preview permission. This is a distinct upstream frontend improvement; it is not evidence that the release-note formula-log symptom was a frontend fix.
- Mingo chart saving validates the source specification, keeps permission-based data scope, handles API HTTP-200 business failures and 401 failures, and offers worksheet/custom-page targets only in an enabled ChartSaveProvider. Feedback validates iframe message origin, source window and message type. The public form broadcasts successful completion and supports the feedback hotkey/display parameters. Human transfer uses public session sharing and the existing native/web customer-service entry.
- AppSettings exposes sandbox configuration, passes status/enable-record IDs, hides production lock/import-upgrade/delete controls, and enforces upstream production restrictions in option sets, aggregation edits, global-variable deletion and backup restoration. App menus expose peer production/sandbox navigation and the mobile production QR link. Admin menus use the 15800/15900 sandbox permissions and keep Router 8 relative paths.

## Code attachment preview and Qiniu

The retained preview flow already renders HTML/script attachments in a sandboxed iframe. Its old `canPreviewHtml()` checked SaaS versus private deployment; that was a real omission. It now checks the upstream configuration contract `md.global.SysSettings.enableCodeAttachmentPreview === true`, so private deployments can explicitly enable online previews and disabled deployments do not expose the renderer.

The fork's custom uploader directly passes the configured upload URL and token into its Qiniu implementation. The implementation accepts both same-origin relative endpoints and absolute Qiniu domains, uses `Authorization: UpToken ...` for chunk requests and supports direct multipart and v1 mkblk/mkfile uploads. This preserves the fork's tested private-deployment upload compatibility instead of restoring a mismatched upstream SDK. Backend-issued direct-Qiniu tokens/URL/CORS still require deployment acceptance.
