## Coverage terminology

- **Source integrated**: final source behavior has been migrated into the fork. This does not imply a browser/backend acceptance pass.
- **Model tested**: targeted executable assertions validate a concrete behavior using controlled inputs.
- **Dependency/entry integration**: the responsible integrator must wire the code to the fork's actual Router 8 and configuration paths.
- **Trace / requires acceptance**: a relevant source path is known, but the release-note symptom has not been reproduced against a 7.5.0 backend.

`7.5.0-source-coverage.json` records each changed source file and separates import/formatting/move-only changes from implementation changes. It compares parsed source with imports and comments excluded, and erases TypeScript in the fork comparison. Static equivalence is intentionally not labeled functional acceptance. A non-match may be an intentional fork enhancement, including React 19, Ant Design 6, Redux Toolkit, Router 8, FullCalendar 7, theme, upload and performance work.

## Quota administration feature migration

The initial inventory's quota entry was subsequently verified as a substantive feature change. The fork's old single Settings class was replaced by typed state/data/actions/save hooks and the upstream's component structure, connected through the existing quota route. The new implementation includes shift-range selection, select-all, bulk edits/removal, numeric versus unlimited mode, quick limits while adding entities, sorting, filtered requests, scroll pagination and usage reset. It covers both attachment usage (`resetUsage({projectId, appIds})`) and workflow usage (`resetUageLimit({projectId, entityIds})`).

Draft rows have explicit metadata and are excluded from persisted row counts and reset candidates. Adding or removing a draft does not change the server total. Append responses merge by entity ID and preserve selection; request sequence checks reject late pages from an old query. Saving records add/edit/delete payloads and a snapshot; cancel restores the most recent snapshot. Both save and reset requests preserve cancellation, ignore superseded responses and keep the current request's loading state. Cancel is disabled while a save is pending.

`quota.spec.ts` passed through the repository harness. It verifies shift-range addition/removal, original-array preservation, draft/server count separation, add/edit/delete payloads, append deduplication, cancel snapshots, protocol-specific sorting, stale response checks, filtering unsaved reset rows, a synchronous double-click reset lock, failed-reset selection retention and late canceled saves. The spec's own tool diagnostics are zero. All nineteen quota TS/TSX production modules transform with production Babel; the actual CLI final strict flags report zero diagnostics in the quota directory.

A final feedback-contract review also removed the message-ID fallback from feedback requests. `getFeedbackTraceId` accepts only a trace provided by history/stream or the actual billing trace. Without one, the feedback action is hidden. Tests verify that an otherwise valid message ID cannot be sent as a trace identifier. Completed stream events now retain the actual backend message ID and trace independently.
