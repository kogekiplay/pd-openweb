# 子表与关联表 store 强类型

本批基于 `d14a2d474`，于 2026-10-10 完成全量检查，继续全仓 TS 严格化目标。没有修改生产环境。

## 状态和公共调用

删除 `SubListStore = any`，按实际实现区分 ChildTableStore 与 RelateRecordTableStore。两个 store 保留完整 Redux 对象，分别声明真实状态、初始化、重置、取消、清空、加载钩子及队列；公开 dispatch 使用有限的已知动作族，行元字段有准确类型，任意控件值保持 unknown。树形追加动作使用同一有限行模型。共享动作的 12 种载荷经过双向兼容类型探针，家族判断只区分已经声明的两个 store，不把未知小对象冒充完整 store。

DataFormat、序列化、唯一值校验、Form store、树形工具、筛选、子表对话框和桌面/移动入口使用真实公共签名。原来把 getState 结果标为 SubListStore 的位置改为状态模型。两种表的不同方法和状态在调用前区分；ref 接收的外层 wrapper 与 registerCell 接收的实际表组件分别建模，替换 store 和卸载时释放订阅。

## 失败、重试和有效行为

- 并发初始化共享在途 Promise，失败可重试。元数据、首轮记录和分页加载失败清除内部/外部加载标志，保留旧记录并呈现错误。子表失败通过真实校验与提交动作阻止保存；成功重试后解除错误，保留父字段原值。
- `initAndLoadRows` 保持原先的“启动加载”语义，Promise 完成不等于记录已加载。子表待赋值队列只在真实 LOAD_ROWS_COMPLETE 时释放，失败和再次失败保留队列。已有记录重试使用父工作表、父记录和控件 ID；新建记录只重试元数据，不向缺失的记录 ID 发请求。
- 关联表首次初始化失败使用 init 重试；已初始化后的刷新/分页失败使用实际 loadRecords，保留当前页、关键词、筛选、排序及未保存修改。网络失败和未知坏行解码都进入错误终态，不伪造空成功结果。错误/未初始化期间不向表单报告成功行数。
- 后台初始化及被动赋值的 Promise 拒绝均有错误收尾。修复事件赋值原位修改 updatedControlIds 导致 Redux immutableCheck 崩溃的问题，保留原始行与取消快照。默认关联记录标题从实际标题控件读取，修复原 filter 数组被当作单个对象的错误。
- 正常状态和载荷的 12 个生产 Babel/实际 RTK 检查点与旧实现一致；桌面/移动普通回调、计数、队列和 ref 有效输入对比保持。缺失总数继续保留旧 undefined 运算产生 NaN 的语义，不将未知总数伪设为零；已知数字计数算法不变。

两个工作流/公开表单工作表入口只标注现有生成 DTO 的 Partial 契约，不增加未经证实的必填字段。这里的契约来自实际前端消费；尚无在线后端 responses/$ref 完整映射证据。没有用少数字段检查或整包断言冒充完整 FormControl/规则/工作表校验。
