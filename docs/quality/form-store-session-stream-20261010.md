## 最终模型和行为

- 表单动作的 payload 与动作 type 配对，reducer 状态、入口 context/ref 及实际 DataFormat 公共方法采用有限模型。Form 入口保留未消费扩展 props 为 unknown，已知值和回调有真实签名。动作、reducer、入口和行规则工具达标；这不代表 DataFormat、子表或事件引擎内部的全部存量代码已强类型化。
- 规则 API 的显式 undefined 字段、子表校验 store、事件入口和分隔线映射使用实际消费 ABI。构造器创建子表 store 的布尔标志与评分数字默认值契约保持。配置加载失败/缺少工作表 ID 会清除加载状态并报告失败；唯一值网络校验失败会调用错误回调并释放加载标志，不制造成功结果。有效动作、新旧规则流程与异步完成顺序对比通过。
- SSO POST 的业务数据保持 unknown，各登录、企业信息、微信签名、JWT 入口提供自己的解码器；保持请求地址、请求头、凭证、AES、回调 receiver 和有效查询参数的原行为。无 `=` 的查询项按空字符串处理。HTTP、JSON、解密和字段失败进入错误回调；Zendesk 的 `succees` 拼写错误修为 `success`，真实回调规格验证填入 JWT 并只提交一次。
- 会话写入继续保留门户 verification=true、HttpOnly、iframe 与域名分支，Cookie 优先级不变。原生 storage 直接使用官方 DOM 类型，原 Getter 次数和抛错路径保持。部署元信息从 unknown 逐级读取，只认可布尔标志；缺少启动配置仍可执行门户强制写入，字符串 `'false'` 不会被误当 HttpOnly 开关。
- 权限 API ID 全数组验证后才写入内存 Map 缓存；UI 五种字符串标志与数值 ID 区分。冷缓存保持拒绝，失败释放待处理请求，原有效过期缓存行为保留。权限组件在 render 中核对组织/所需权限上下文，切换时立即隐藏旧授权，晚到回调与卸载回调不会恢复旧内容。
- JSONL 通用解析返回 unknown；字段推荐、字段填写、记录行和应用优化调用方解码各自实际读取的字段。AI 控件值格式化使用 unknown 输入、按控件验证实体/附件/子表行后返回实际序列化字符串。未知元信息保留，有效格式化不变。坏布局字符串不进入 NaN 行列号；部分解析器可安全处理 `hasOwnProperty`/`constructor`/`__proto__` 数据键，避免覆盖其自身检测或对象原型。
