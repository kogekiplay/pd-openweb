## 类型检查发现的运行问题

`loadGroupMore` 原来用 Lodash 读取 `${groupKey}.pageIndex`，同时存在 `g` 和 `g.pageIndex` 这两个分组时可能命中整键对象，下一页变成字符串而非数值。现在先读取确切分组，再取它的 pageIndex。规格加载真实 action thunk，验证实际请求页码、分组键、取消信号、加载状态和返回记录插入；六种场景覆盖带点键、同名整键冲突、缺失、undefined 和零页码。相同规格对修改前代码会失败。

导航树内部 genTree 的缺省参数对象引用尚未初始化的 info，触发已有 TS2373；删除了该错误缺省对象。所有有效调用原本都显式传对象，有效输入运行不变，缺参仍然是错误调用。记录查找补显式 return undefined，与原先函数末尾隐式返回等价。

生产 Babel 擦除类型及注释后，所有本批修改的 reducer 和公共/层级 action 均与原提交逐字节相同。运行差异限于上述分页读取、无效缺参默认对象和等价末尾 return。
