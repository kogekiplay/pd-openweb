## 类型与运行行为

- 工作表配置缓存按七种实际键区分数字偏好和已序列化字符串。公开写入签名使用配对参数联合，错误的键/值组合、扩大键联合或显式泛型不能绕过检查。读取 JSON 从 unknown 解码，不把样式对象冒充字符串；既有数字、字符串和缺失值行为保持。修复旧容量淘汰代码没有调用 `.pop` 的问题，写入后最多保留 30 条并保留当前写入项。现有 HAP UUID/视图 ID 按对象插入顺序更新；整数形式 ID 的历史顺序受 JavaScript 对象枚举规则影响，不宣称完整跨写入 LRU。
- KV 写入/删除保留 abort 请求句柄、moduleType、静默参数和三天过期策略，响应保持 unknown。读取仅接收后端存储的序列化文本。企业微信保留共享 debounce 实例及 latest/flush/cancel 行为；本地草稿索引使用 string[]，坏索引可恢复，缺少 ID 不写入伪身份项。
- 新建记录恢复同时支持时间/值包与旧直接字段映射，错误或空草稿释放加载状态。已有记录仍按更新时间判断是否恢复；远程读取失败有对应错误收尾。通用字段 JSON 与真实记录行分开：普通 JSON 的数字 `rowid` 被完整保留，真正记录行的 `rowid` 仍要求字符串。实际 getRecordTempValue → 缓存 → 新建记录恢复 → parseRecordTempValue 链路验证了嵌套 JSON、零/false、子表行及两种存储格式。
- 自定义事件、请求映射和响应映射采用各自有限协议；动态行/单元格保持 unknown 并在实际消费处收窄。失败、跳过和执行完成均释放 blur/change 加载状态。后台 CREATE 保留原动作顺序，后续 LINK 可即时执行，同时为已启动请求接上错误处理，并等待其结束再完成事件。声音播放拒绝也有错误收尾。
- 缺少事件目标/查询 ID 不会匹配没有 ID 的占位控件或发出目标请求。查询响应允许正总数对应空/遗漏当前页，关联响应只检查实际消费的 resultCode/data，不凭空要求 count。评分保留历史字符串、数字、null 等标量的原加法行为；模板、查询配置、回调及四处 Search/OCR 使用同一真实载荷模型。

这些边界达标不代表 DataFormat、记录组件、全部 API 或子表 store 已完成强类型化。SubListStore 的后续公共模型和调用方闭合仍在工作区独立推进，没有混入本批。
